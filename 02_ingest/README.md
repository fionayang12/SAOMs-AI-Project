# Ingest

Builds derived network data from source files.

- `extract_demo_subset.py`: pulls selected ego networks from the full-corpus
  files into a self-contained demo folder. Run on a machine holding the full
  corpus; commit only the output.
- Full USPTO build chain: The raw patent document data for the analyses are obtained from PatentsView, a patent data platform supported by the Office of the Chief Economist at the U.S. Patent and Trademark Office (USPTO). PatentsView builds on the USPTO's raw patent records and releases cleaned, linked tables, including disambiguated inventors, assignees, and locations. Five bulk files for granted U.S. patents, downloaded in July 2025, are used: g_inventor_disambiguated, g_application, g_assignee_disambiguated, g_ipc_at_issue, and g_us_patent_citation. Inventor and assignee identities are taken directly from PatentsView's disambiguated inventor_id and assignee_id, and no additional name matching is performed. The only adjustment is that the 2,029 cases in the raw table in which one inventor_id appears twice on the same patent are collapsed into single inventor–patent records. Following Hoisl (2007), a patent's assignee is treated as the employer of all its inventors, so only single-assignee patents are retained. An inventor is coded as moving when consecutive patents list both a new assignee and a new location. Inventors with more than two moves in a calendar year are classified as third-party inventors and excluded from estimation. Each pair of inventors on the same patent forms one undirected co-invention tie, dated by the patent's application date. Because every patent has a single assignee, each tie links colleagues at the same firm.
